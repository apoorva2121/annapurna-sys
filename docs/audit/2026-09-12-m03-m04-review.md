# M03 / M04 adversarial review — 2026-09-12

Two rounds. The first found the defects; the second checked the fixes and, more usefully, checked
whether the *tests* for those fixes can actually fail.

`docs/engineering-guardrails.md` G-2 calls that the honest harness: **a test that cannot fail is
worse than no test**, because it buys confidence nothing earned. Round one found three existing
tests in exactly that state, which is why round two was spent proving the new ones are not.

---

## What round one found

Grouped by family rather than by file, because each family is one mistake made in several places.

| Family | The defect | Where it is fixed |
|---|---|---|
| **Tenancy** | `RecipeLine`'s docstring claimed a composite foreign key kept a line's component on the line's tenant. There was none. `uq_stock_item_id_restaurant` was created and commented as "the target of the composite foreign keys below" and was the target of nothing — the only protection was one check inside `StockService.save_version`, and M04 explicitly hands a *second* write path to a later module | migration `0013`, `app/models/stock.py` |
| **Cross-tenant denial of service** | The three `uq_recipe_current_*` partial indexes were global, and nothing validated `recipe.modifier_id` at all. Together, one restaurant could take another's slot and permanently prevent the owner from creating their own — a 500 with no recovery, on their own data | migration `0013`, `StockService._require_owner_exists` |
| **Money** | A modifier's `price_delta` is added to every order line carrying the option. It sat behind `menu.manage` and wrote no audit row, so "Extra paneer +₹150" was reachable by exactly the person `seed/organization.yaml` denies pricing to, leaving no trace | `api/v1/staff/menu.py`, `services/menu.py` |
| **Cost visibility** | Every stock-item read carried `current_unit_cost` and every recipe read carried `unit_cost`, so the whole ingredient price list was one `GET /stock-items` away from anyone who could open a recipe. The separation this module calls its headline did not exist | `schemas/stock.py`, `api/v1/staff/stock.py` |
| **One rule, counted twice** | The save-time depth walk seeded its chain with the owner's code — needed to catch a self-referential preparation — and then counted that code toward the depth. It refused at three what `cost_of` and `seed/validate.py` both allow at three, which is an ordinary Indian recipe and ships in the seed | `services/costing.py` |
| **Inert tests** | Three, see below | `tests/` |
| **Unreachable screens** | M03's and M04's screens had routes and no links. M04 had no recipe editor at all, so a chef could not write a recipe — the module's own headline, deferred on a design question | `AppShell.tsx`, `RecipeScreen.tsx` |

## What the reviewers could not tell me

Three reviewer agents died on a session rate limit and a fourth stalled partway through the
mutation list. The table above was finished by hand. Two consequences worth recording:

- **A subagent's cleanup reverted work it did not own.** It ran a repository-wide revert to get a
  clean tree, which reached uncommitted work in the parent session. Nothing was lost — it had
  stashed rather than discarded — but the lesson stands: mutation testing belongs on a committed
  tree, and a mutation agent should revert only files it names.
- The frontend and documentation charter was never run by an agent. The findings below came from
  reading my own work, so they are the ones most likely to be incomplete.

## Found by re-reading my own fixes

| Finding | Consequence |
|---|---|
| The recipe editor could not change a quantity — only Add and Remove | Correcting 200 g to 180 g meant deleting the line and retyping it, on the screen whose entire purpose is a chef correcting library quantities. `docs/manual-tests/M04-recipes.md` step D2 instructed the user to do exactly what the screen could not do |
| **Confirm** acted on the saved version while the draft held unsaved edits | A chef could change three lines, press Confirm, and mark the *old* numbers as checked. `confirmed_at` is what the dish-cost screen reads to decide whether a cost is a proposal or a fact |
| The navigation fix went on the home page rather than the header | Helps somebody who has just signed in and nobody else. A chef at the pass is already inside the app |
| I wrote that M02's screens were unlinked | They were always in the header. Only M03's and M04's were missing. Corrected in the code comment and in the commit that followed |
