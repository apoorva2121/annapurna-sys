# Backlog

Ideas that arrived mid-module. **Nothing here is scope** until it is promoted into
`docs/modules.md` deliberately, between modules — never during one.

This file exists because the vision document has 36 sections and the single most reliable way to
finish nothing is to act on all of them.

| Idea | Source | Notes |
|---|---|---|
| Upgrade vitest 3 → 5 for GHSA-82fw-gwwq-j7x9 | M00, 2026-09-09 | Path traversal in `@vitest/mocker`. **Dev dependency only — never in the production bundle**, and the gate is `npm audit --audit-level=high`, which this moderate does not trip. | Notify the owner when a manager changes someone's roles | M01, 2026-09-10 | Requested during M01: managers hold `employee.role.assign`, and the owner should hear about it. M01 writes the `audit_log` row (actor, target, before/after, ip, timestamp), so **the event is already captured and nothing is lost**. What is missing is delivery — the `notification` table, severity tiers and channels are M14's deliverable, and building them here would be building M14. M14 turns these existing rows into notifications; no M01 change needed then. |
| Disambiguate a login identifier that exists in two organizations | M01, 2026-09-10 | Email and phone are unique *per organization*, so one address can legitimately belong to two (a consultant working for two restaurant groups). Login currently resolves globally and refuses an ambiguous match with the standard identical error, which is safe but locks that person out. Fix when it first happens: an organization picker on the login form, or a per-tenant subdomain. |
| Package `seed/` into the backend image | M01, 2026-09-11 | `make seed` reads `seed/organization.yaml`, which lives at the repository root while the backend's Docker build context is `./backend` — so the image cannot contain it. Compose mounts it read-only and the loader searches `SEED_DIR`, `/app/seed`, then the working copy, which covers local and a staging box running the same compose file. A standalone image (ADR 0005's deploy unit) would need the data inside it: either move the build context to the repo root, or have M15's generator ship the dataset as package data. **Do this with M15**, which owns the full seed generator anyway. |
| Initialise shadcn/ui properly | M01, 2026-09-11 | `docs/ui/conventions.md` says "the component library **is** the design system — do not hand-roll a component that shadcn provides", but M00 never ran `shadcn init`: it established its own semantic tokens (`--critical`, `--success`, …) and the deps (cva, clsx, tailwind-merge) without the components. M01's Button, Field and Notice are built on those tokens and follow shadcn's prop shape so the swap is mechanical. Decide before M07, which is the first module with real component volume — either adopt shadcn for real, or amend conventions.md to describe what we actually do. Leaving the doc and the code disagreeing is the bad option. |
| Reset another employee's password from the UI | M01, 2026-09-11 | `POST /staff/employees/{id}/password` exists, is permission-gated and is tested; the M01 frontend deliverable list did not include a screen for it, so there is no button. An owner currently needs the API. Small — add it to the employee page when M02 touches that screen. |
